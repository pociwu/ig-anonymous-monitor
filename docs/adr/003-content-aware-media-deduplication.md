# ADR 003：以內容指紋去重並保留最佳畫質媒體

- 狀態：已接受
- 日期：2026-07-29

## 背景

匿名檢視網站可能以不同 URL、媒體鍵、解析度或壓縮方式重複提供同一個 Instagram 媒體。現有 SHA-256 機制可避免完全相同的檔案重複寫入，但資料庫仍保留多筆媒體紀錄，儀表板因此重複顯示；不同壓縮版本也無法用 SHA-256 合併。

## 決策

1. 去重範圍限定在單一 Instagram 帳號內，不跨帳號合併。
2. 完整 SHA-256 相同時直接判定為重複。
3. 圖片另以 Pillow 感知雜湊判定相同內容；預設要求長寬比差異不超過 1%，雜湊距離不超過 4。
4. 影片以 ffprobe 取得品質資料，以 ffmpeg 擷取前段、中段、後段代表畫面；預設要求長度差異不超過 1 秒或 1%，且三張畫面都符合圖片門檻。
5. 裁切、浮水印、文字覆蓋或重新編輯版不自動合併。
6. 每組重複媒體只顯示 Canonical media。照片依像素總數、檔案大小選擇；影片依像素總數、位元率、檔案大小選擇；完全相同時保留最早下載版本。
7. Duplicate record 保留在資料庫並指向 Canonical media，以避免後續巡檢重新下載；它不發 Telegram 附件，也不出現在儀表板。
8. 後續取得更高畫質版本時升級 Canonical media，不視為新增媒體、不發 Telegram，只記錄日誌並刪除未被其他紀錄引用的低畫質檔案。
9. 既有資料透過 `--dedupe-media --dry-run` 預覽，再以 `--dedupe-media --apply` 套用，不在資料庫啟動遷移時自動刪除。
10. 缺少 ffmpeg／ffprobe 時，影片退回 SHA-256 精確去重並記錄警告；圖片與其他巡檢功能不受影響。
11. 儀表板將媒體依 Posts、Stories、Highlights 分區，每區再區分照片與影片；同一 Canonical media 即使來自多個來源，也只顯示一份並保留來源關聯。
12. 儀表板使用兩層頁籤：第一層為貼文、Stories、Highlights，第二層為全部、照片、影片；頁籤顯示媒體數量，切換時不重新載入頁面。

## 後果

- 同帳號的媒體頁只顯示一份最佳畫質內容。
- 資料庫需要保存內容指紋、品質資訊與 Canonical media 關聯。
- 初次清理既有媒體會讀取全部已下載檔案，影片指紋計算可能耗時。
- 感知雜湊門檻可由設定調整，但過度放寬可能誤合併相似內容。
